## 问题与目标

- 要解决的问题：运营与客服需要在单一 Web 应用中查看并管理 B2C 订单，替代 Excel 台账
- 成功标准：P0 用户路径（登录 → 订单列表 → 筛选 → 详情 → 模拟支付/取消）在 staging 端到端通过；P0 缺陷为 0

## 范围

### In Scope
- 账号密码登录（内部运营用户）
- 商品目录只读浏览（支撑下单上下文）
- 订单列表：按状态、日期筛选；分页
- 订单详情：行项目、金额、状态时间线
- 模拟支付：待付款 → 已付款
- 取消：仅待付款可取消

### Out of Scope / 非目标
- 真实支付（微信/支付宝/银行卡）
- 物流发货与轨迹
- 多租户 / 门店维度
- 移动端原生 App
- 对外公开注册与 C 端营销页

## 需求

### REQ-ORDER-001 订单列表与筛选
- 优先级：P0
- 摘要：运营用户可按状态、创建日期区间查询订单并分页浏览
- 验收：给定 50 条种子数据，筛选「待付款 + 近 7 天」返回正确子集；空结果显示明确文案；API 与 UI 分页一致

### REQ-ORDER-002 模拟支付
- 优先级：P0
- 摘要：对待付款订单执行模拟支付，状态变为已付款且不可回退
- 验收：仅 `PENDING_PAYMENT` 展示支付按钮；成功后状态为 `PAID`；重复点击幂等或明确拒绝

### REQ-CATALOG-001 商品只读浏览
- 优先级：P1
- 摘要：订单详情可跳转查看关联 SKU 当前信息（只读）
- 验收：下架 SKU 仍可在历史订单详情展示快照价格，跳转页显示「已下架」
