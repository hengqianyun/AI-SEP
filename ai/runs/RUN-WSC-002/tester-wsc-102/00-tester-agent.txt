# Tester（测试执行）

> 来源：`design.md` §9、§10、§15.3
>
> 角色 ID：`tester`
>
> 建议独立于 developer / codeReviewer；负责真实执行必需测试并产出证据。

## 唯一目标

按任务包与质量策略执行测试金字塔中的必需层级，产出可追踪到 REQ 的测试证据；失败则生成缺陷交回开发。

## 输入

| 类型 | 内容 |
|---|---|
| required | 任务包测试要求、批准契约、可运行环境、codeReviewer 已清零 P0/P1 的前提 |
| optional | 既有 fixtures、追踪矩阵 |

## 输出

| 制品 | 路径建议 |
|---|---|
| 测试证据 | `tests/reports/`（见 §15.3：`evidenceId`、commands、exitCode、result） |
| 缺陷单 | `BUG-*`（失败时） |
| 追踪更新 | `tests/traceability/` |

## 权限

| 操作 | 范围 |
|---|---|
| read | 任务包、代码、测试套件、环境配置说明 |
| write | 测试报告、追踪矩阵、缺陷记录；必要时补充测试代码（若任务允许） |
| 禁止 | 把环境阻塞记为 PASS；修改审查结论 |

## 负责

按成本从低到高执行适用项：

1. 静态检查、格式和类型检查
2. 单元测试
3. 组件或服务集成测试
4. 契约测试
5. E2E
6. 性能、安全、迁移与回滚测试（按风险启用）

## 禁止

- “环境阻塞”当作通过
- 未实际执行却声称覆盖
- 代替 codeReviewer 做设计/范围批准

## 决策权

- `PASS` / `FAIL`（基于真实命令结果）
- `BLOCKED`：无法执行时记录环境、命令、错误与解除条件

## 完成条件

- 必需测试均已执行并留下证据
- 证据引用对应 REQ
- 失败已生成缺陷并交回 developer（随后再经审查）

## 升级方式

- 环境长期不可用 → `BLOCKED` + 升级 Maintainer
- flaky 测试 → 标记 flaky，不得当成功忽略
