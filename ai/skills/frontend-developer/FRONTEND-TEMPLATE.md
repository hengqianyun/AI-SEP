# Frontend Developer Skill 填写模板

> 前端负责人复制本结构填写 `SKILL.md`。尖括号内容必须替换；不适用项写 `N/A` 及原因。  
> 本 Skill 只写“怎么做”；技术选型与版本边界应引用 Organization Rule。

## 1. 元数据

```yaml
---
id: skill.frontend-developer
version: 1.0.0
status: draft
owner: <前端负责人或团队>
inputSchema: task-package@1
compatibleRoles: [developer]
appliesTo:
  paths:
    - <前端源码路径，例如 frontend/**>
relatedRules:
  - RULE-ORG-STACK
  - RULE-ORG-CODING
  - RULE-PROJECT-LAYOUT
---
```

- `owner` 应是可批准本 Skill 的角色/团队。
- `paths` 必须匹配真实目录；monorepo 精确到应用或包。
- `relatedRules` 只引用已存在且适用的 Rule ID。

## 3. 实现工作流

```markdown
## 实现工作流

1. 读取任务包、REQ、冻结契约与适用 Rule。
2. 确认目标文件位于 `allowModify`。
3. 查找同类实现作为结构参考：`<示例路径或查找规则>`。
4. 先明确测试/验收场景，再做最小变更。
5. 按验证矩阵从低成本到高成本执行命令。
6. 输出变更摘要、REQ 映射、命令与实际结果。
```

## 7. 禁止事项与例外

```markdown
## 禁止事项

- 不得引入 `<第二套框架/库/模式>`；例外须有批准 ADR。
- 不得绕过统一 API Client、鉴权、错误处理或 Design Token。
- 不得关闭 Lint、跳过测试或弱化类型来掩盖问题。
- 不得提交构建产物、真实环境文件、调试日志或无关格式化。
- 不得扩大 `allowModify`；边界不足时升级。

## 例外

| 规则 | 允许条件 | 批准身份 | 必须留下的证据 |

| `<规则>` | `<条件>` | `<身份>` | `<ADR/评审记录>` |
```

## 9. 激活检查

- [ ] 前端负责人完成所有占位并实际执行命令

- [ ] Tech Lead 确认与 Rule/架构无冲突
- [ ] `context-map.yaml` 已配置真实前端路径
- [ ] Owner 将 `status` 改为 `active`
