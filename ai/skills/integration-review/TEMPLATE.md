# Integration Review Skill 填写模板

> 集成审查负责人复制本结构填写 `SKILL.md`。尖括号内容必须替换；不适用项写 `N/A` 及原因。  
> 本 Skill 关注**并行束合并后**的跨任务行为，而非重复单任务自测。  
> 前端入口冒烟由前端与 QA 协作填写；无前端时写 N/A。  
> 已填写示例：[`EXAMPLE.md`](./EXAMPLE.md)（仅展示粒度，不代表默认技术栈）。

## 1. 元数据

```yaml
---
id: skill.integration-review
version: 1.0.0
status: draft
owner: <集成审查负责人或 Tech Lead>
compatibleRoles: [integrationReviewer]
relatedSkills:
  - skill.tester
  - skill.parallel-planner
  - <frontend-developer 如适用>
---
```

## 2. 适用范围与前置条件

```markdown
## 适用范围

- 触发：并行任务束合并后 / 发布前集成门禁
- 工作目录：`<真实目录>`
- 依赖安装/构建：`<可复制命令>`
- 环境配置：`<示例配置来源；不得包含真实密钥>`
- 依赖服务或替身：`<启动方式、健康检查或 N/A>`

## 前置条件

- 束内任务均已完成且合并顺序符合 `mergeAfter`
- 单任务强制测试已有证据；本 Skill 聚焦跨模块交互
```

## 3. 审查工作流

```markdown
## 审查工作流

1. 核对并行任务列表、写集声明与实际合并顺序。
2. 确认无未声明写冲突残留。
3. 执行契约测试与冒烟路径（按触发条件）。
4. 将失败归因到具体责任任务或环境阻塞。
5. 输出集成结论与证据路径；`BLOCKED ≠ PASSED`。
```

## 8. 激活检查

- [ ] 冒烟与契约命令可从指定目录复制执行，或有明确 N/A
- [ ] 至少覆盖一条真实跨模块路径（有前端则含入口）
- [ ] QA 已复核通过标准；阻塞或未执行不记为通过
- [ ] Owner 将 `status` 改为 `active`
