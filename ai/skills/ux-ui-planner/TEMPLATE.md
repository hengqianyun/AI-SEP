# UX/UI Planner Skill 填写模板

> UX/UI 规划负责人复制本结构填写 `SKILL.md`。尖括号内容必须替换；不适用项写 `N/A` 及原因。  
> 本 Skill 只写体验规划输入与交付要求；**不代替前端选型或实现技术栈**。  
> 无 UI 的项目：在 `policies.yaml` 禁用本角色，并在本 Skill 顶部写明 N/A。  
> 已填写示例：[`EXAMPLE.md`](./EXAMPLE.md)（仅展示粒度，不代表默认技术栈）。

## 1. 元数据

```yaml
---
id: skill.ux-ui-planner
version: 1.0.0
status: draft
owner: <产品/体验负责人>
compatibleRoles: [uxUiPlanner]
relatedPolicies:
  - optionalRoles.uxUiPlanner
relatedRules:
  - <品牌/内容/无障碍相关 Rule；无则省略>
---
```

- 若项目禁用 UX：保持说明性 N/A，或不要将本 Skill 装载为 `active` 执行项。

## 2. 无 UI / 禁用时的 N/A 记录

无 UI 或不启用 UX 规划时，**优先填写本节并跳过后续实现段落**：

```markdown
## 本 Skill 状态：N/A

- 依据：`<policies.yaml optionalRoles.uxUiPlanner 决策位置 / P-05>`
- 原因：`<无 UI/UX 规划需求的原因>`
- `enabled`: false
- 确认人：`<Product Owner + Tech Lead>`
- 确认日期：`<YYYY-MM-DD>`
- 重评触发：`<出现何种情况时重新启用>`
```

启用 UX 时本节写 `N/A — 本项目已启用 UX 规划`。

## 3. 适用范围与前置条件（启用时）

```markdown
## 适用范围

- 覆盖终端：`<Web / 小程序 / App / 其他；业务范围，不指定框架>`
- 关键场景来源：`<PRD 章节或研究材料>`
- 设计系统状态：`<已有路径 / 暂无，使用文字稿>`

## 前置条件

- 产品范围与非目标已冻结或可引用
- 与领域规则冲突时升级 Product Owner，不自行改范围
```

```markdown

- 目标用户与关键场景来源：`<PRD 章节或研究材料>`

- 组件库/共享组件入口（技术侧）：`<真实路径或 N/A>`
- 设计令牌来源（技术侧）：`<真实路径或 N/A>`
- 图标/字体/静态资源入口：`<真实路径或 N/A>`

```

## 5. 体验交付要求

```markdown
## 体验交付要求

- 必须描述的页面/流程状态：`<加载、空、错误、成功等>`
- 交互与反馈要求：`<任务所需最低内容>`
- 可访问性目标：`<项目批准要求或待确认负责人>`
- 响应式/终端范围：`<业务要求，不指定实现技术>`
- 交接证据落盘位置：`<标注、流程、文案、验收说明路径>`
```

## 6. 规划输出约束

```markdown
## 规划输出约束

- 优先复用条件：`<何时必须复用现有组件/模式>`
- 新增组件/令牌条件：`<何时允许及批准角色>`
- 设计缺口处理：`<如何记录并交还产品/设计确认>`
- 禁止规划内容：`<与已批准技术栈/编码约定冲突或越权选型>`
- 冲突升级：`<与业务规则冲突时的角色与记录位置>`
```

## 7. 评审焦点与输出

```markdown
## 评审焦点

- 关键用户路径、状态与空态
- 与品牌/既有规范一致性
- 不代替 Product Owner 做范围裁决
- 不代替前端负责人选择框架或库

## 输出格式

- 覆盖页面/流程：`<列表>`
- 状态与文案要点：`<摘要或路径>`
- 无障碍与多端备注：`<说明>`
- 缺口与升级项：`<列表 + Owner>`
- 交接包路径：`<路径>`
```

## 8. 激活检查

- [ ] 已启用：设计系统路径或“暂无、使用文字稿”已明确
- [ ] 已启用：关键状态、交接证据可被规划角色直接使用
- [ ] 已禁用：顶部 N/A、原因、确认人、重评触发完整
- [ ] 未通过本 Skill 引入未批准的前端技术选型
- [ ] Owner 将 `status` 改为 `active`（或确认保持 N/A 不装载）
