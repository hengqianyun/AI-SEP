# Backend Developer Skill 填写模板

> 后端负责人复制本结构填写 `SKILL.md`。尖括号内容必须替换；不适用项写 `N/A` 及原因。  
> 本 Skill 只写“怎么做”；技术选型与版本边界应引用 Organization Rule。  
> 勿预设具体语言或框架；栈未定时 `SKILL.md` 保持 `draft`。  
> 已填写示例：[`BACKEND-EXAMPLE-SPRING.md`](./BACKEND-EXAMPLE-SPRING.md)（仅展示粒度，不代表默认技术栈）。

## 1. 元数据

```yaml
---
id: skill.backend-developer
version: 1.0.0
status: draft
owner: <后端负责人或团队>
inputSchema: task-package@1
compatibleRoles: [developer]
appliesTo:
  paths:
    - <后端源码路径，例如 backend/** 或 services/**>
relatedRules:
  - RULE-ORG-STACK
  - RULE-ORG-CODING
  - RULE-PROJECT-LAYOUT
---
```

- `owner` 应是可批准本 Skill 的角色/团队。
- `paths` 必须匹配真实目录；monorepo 精确到服务或包。
- `relatedRules` 只引用已存在且适用的 Rule ID。
- 通用执行底线：与 `skill.developer` 一并按路径装载；本文件不写前端技术栈正文。

## 2. 适用范围与前置条件

```markdown
## 适用范围

- 服务/包：`<路径>`
- 技术栈：引用 `<RULE-ID>`（语言、框架、数据存储、迁移工具）
- 包管理器或构建工具与锁文件：`<例如 go.mod / pom.xml / requirements.txt + 锁文件>`
- 运行时版本来源：`<例如 .tool-versions、sdkman、Dockerfile 基础镜像标签>`
- 命令工作目录：`<仓库根目录或明确子目录>`

## 前置条件

- `<依赖服务（DB/缓存/消息等）、环境变量样例、代码生成或迁移前置步骤>`
- 禁止读取或提交真实密钥；本地变量从 `<示例文件>` 创建
- 前置工具及版本验证：`<可复制命令>`
```

## 3. 实现工作流

```markdown
## 实现工作流

1. 读取任务包、REQ、冻结契约与适用 Rule。
2. 确认目标文件位于 `allowModify`。
3. 查找同类实现作为结构参考：`<示例路径或查找规则>`。
4. 先明确测试/验收场景（含契约与数据影响），再做最小变更。
5. 按验证矩阵从低成本到高成本执行命令。
6. 涉及 schema/迁移时先完成迁移验证与回滚说明，再宣称实现完成。
7. 输出变更摘要、REQ 映射、命令与实际结果。
```

## 4. 验证矩阵

```markdown

所有命令从 `<工作目录>` 执行。

| 场景 | 命令 | 必须执行条件 | 通过标准 |
|---|---|---|---|
| 安装/恢复依赖 | `<命令>` | 首次/锁文件或清单变化 | 退出码 0，锁文件无意外变化 |
| Lint / 静态检查 | `<命令>` | 每任务 | 新增错误为 0 |
| 类型/编译检查 | `<命令或 N/A>` | `<条件>` | 退出码 0 |
| 相关单测 | `<命令，可带测试路径>` | 每实现任务 | 退出码 0 |
| 全量单测 | `<命令>` | 共享模块/合并前 | 退出码 0 |
| 集成测试 | `<命令或 N/A>` | API/数据访问/跨模块变化 | 退出码 0 |
| 构建/打包 | `<命令>` | 每任务或合并前 | 退出码 0，产物符合约定 |
| 迁移（up） | `<命令或 N/A>` | schema/数据变更 | 退出码 0；前置条件已满足 |
| 迁移验证/回滚 | `<命令或 N/A>` | 有迁移任务 | 验证通过；回滚命令可执行或有批准例外 |
| 本地启动/健康检查 | `<命令>` | 需联调或冒烟 | 服务启动且健康检查通过、无阻塞错误 |
```

## 5. 实现约定

```markdown
## 目录与实现约定

### 模块与边界
- 源码根目录：`<路径>`
- 模块/包边界：`<规则与真实路径>`
- 同类实现范例：`<现有文件>`
- 配置与环境样例：`<路径>`；禁止提交真实密钥

### API 与契约
- API 定义/路由入口：`<路径>`
- 请求/响应与错误码约定：引用 `<RULE-ID 或文件章节>`
- 鉴权与授权落点：`<统一中间件/过滤器路径>`
- 日志字段与关联 ID：引用 `<规则或范例>`
- 禁止在 handler 中直接：`<绕过统一错误处理、硬编码下游地址等>`

### 数据访问与迁移
- 数据访问层位置：`<路径>`
- 事务与仓储边界：`<规则>`
- 迁移文件目录与命名：`<路径与模式>`
- 迁移前置条件、验证与回滚责任：`<引用 BE/Rule 或本地说明>`
- 禁止业务代码直接：`<绕过 DAL、手写破坏性 DDL 等>`
```

每条约定尽量提供“规则 + 真实范例路径”，避免 Agent 自创第二套模式。

## 7. 禁止事项与例外

```markdown
## 禁止事项

- 不得引入 `<第二套语言/框架/数据访问模式>`；例外须有批准 ADR。
- 不得绕过统一 API 错误处理、鉴权、日志或数据访问层。
- 不得关闭 Lint、跳过测试、弱化类型/编译检查或硬编码环境来掩盖问题。
- 不得在未经验证的情况下提交破坏性迁移；回滚方案缺失时不得宣称完成。
- 不得提交构建产物、真实环境文件、调试日志或无关格式化。
- 不得扩大 `allowModify`；边界不足、涉及共享契约或安全边界时升级。

## 例外

| 规则 | 允许条件 | 批准身份 | 必须留下的证据 |
|---|---|---|---|
| `<规则>` | `<条件>` | `<身份>` | `<ADR/评审记录>` |
```

## 8. 开发者输出

```markdown
## 提交审查前自检

- [ ] 变更全部位于 `allowModify`
- [ ] 每个变更关联 REQ
- [ ] 遵循指定范例，或有 ADR 说明偏离
- [ ] 所有适用验证命令已执行（含迁移相关项）
- [ ] 未执行项写明原因、风险和解除条件
- [ ] 环境阻塞记为 `BLOCKED`，未宣称通过

## 输出格式

- 任务：`<TASK-ID>`
- 关联需求：`<REQ-ID 列表>`
- 修改文件：`<路径列表>`
- 实现摘要：`<按需求说明>`
- 迁移影响：`<无，或 up/验证/回滚说明>`
- 已执行验证：`<命令 → PASSED/FAILED/BLOCKED>`
- 未执行验证：`<无，或原因 + 解除条件>`
- 已知风险：`<无，或风险 + Owner>`
```

## 9. 激活检查

- [ ] 后端负责人完成所有占位并实际执行命令
- [ ] 测试人员（QA）确认测试触发条件与命令
- [ ] Tech Lead 确认与 Rule/架构无冲突
- [ ] `context-map.yaml` 已配置真实后端路径并装载 `skill.backend-developer`（及 `skill.developer`）
- [ ] Owner 将 `status` 改为 `active`
