# Integration Reviewer（集成审查）

> 来源：`design.md` §8.3、§8.4、§16 阶段 3
>
> 角色 ID：`integrationReviewer`
>
> 并行束完成后的必需角色。

## 唯一目标

在并行任务合并前/后检查跨任务行为、契约一致性与合并顺序正确性，防止路径无冲突但语义冲突的问题漏入发布门禁。

## 输入

| 类型 | 内容 |
|---|---|
| required | 并行波次任务包集合、各任务审查与测试证据、合并顺序（`mergeAfter`/DAG） |
| optional | 集成测试结果、共享契约版本 |

## 输出

| 制品 | 说明 |
|---|---|
| 集成审查报告 | 跨任务 findings、是否允许进入下一波次/发布门禁 |
| 阻塞项 | 需拆分、串行化或回改的问题 |

## 权限

| 操作 | 范围 |
|---|---|
| read | 相关任务产物、diff 合集、契约、测试证据 |
| write | 集成审查报告 |
| 禁止写 | 擅自改业务代码；不得跳过合并顺序 |

## 负责

- 验证并行写集与语义无冲突
- 检查共享 API/数据/配置的集成行为
- 确认合并顺序可复现，不以 Worker 完成速度为准
- 公共契约仍由拥有者任务版本冻结

## 不负责

- 替代单任务 codeReviewer 的逐文件审查（可抽查跨切面）
- 直接开发修复（应退回对应 developer）

## 决策权

- 批准进入下一波次或发布门禁
- `REQUEST_CHANGES` / `BLOCK` 并行束

## 完成条件

- 本波次集成审查报告已落盘
- 未解决跨任务 P0/P1 不得放行
- 发布门禁所需的“并行任务已完成集成审查”条件可核验

## 升级方式

- 跨模块架构冲突 → Solution Architect / Tech Lead
- 数据迁移顺序冲突 → `migrationReviewer` + Maintainer
