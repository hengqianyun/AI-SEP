| 包管理工具 | <名称> | <版本约束> | <范围> | <角色> |

### 允许与禁止
- 允许的补充库及用途：<库/类别、用途、边界>
- 禁止引入：<库/类别及原因>

完成检查：
- [ ] 框架、工具和版本边界均明确且可追溯

- [ ] 适用路径与仓库实际范围一致
- [ ] 前端团队与 Tech Lead 已确认，没有个人偏好被直接设为规范

## FE-04

**Frontend Developer Skill**

交付位置：`ai/skills/frontend-developer/SKILL.md`。

必须以 [`ai/skills/frontend-developer/FRONTEND-TEMPLATE.md`](../ai/skills/frontend-developer/FRONTEND-TEMPLATE.md) 为填写基线，不在此重复模板正文。职责顺序如下：

1. **前端负责人/前端团队起草**：填写全部占位符、真实路径、前置条件、实现约定和可复制命令，并亲自试跑。
2. **QA 复核测试命令**：核对 lint、类型检查、单测、构建、启动及适用的组件/E2E 命令，确认触发条件、工作目录和通过标准。
3. **Tech Lead/Owner 激活**：确认与 FE-01～FE-03、上下文映射及项目规则无冲突后，才将 `status` 从 `draft` 改为 `active`。

填写与复核记录：

```markdown
## FE-04 交付记录
- 起草人/团队：<前端负责人或团队>
- 适用路径：`<真实路径 glob>`
- 模板版本/提交：<FRONTEND-TEMPLATE.md 的版本或提交引用>
- 命令工作目录：`<真实目录>`
- 前端试跑证据：<命令、日期、结果记录位置>
- QA 复核人：<测试责任人>
- QA 复核证据：<逐项命令结果记录位置>
- Tech Lead/Owner：<激活批准人>
- 激活日期：<YYYY-MM-DD 或待批准>
- 状态：<draft|active>
```

完成检查：
- [ ] 已按指定 `FRONTEND-TEMPLATE.md` 填完，所有占位符已替换或有合理 N/A
- [ ] lint、类型检查、单测、构建、启动等适用命令可从注明目录复制执行
- [ ] 前端负责人/团队已完成起草和实际试跑
- [ ] QA 已复核测试命令、触发条件与通过标准
- [ ] Tech Lead/Owner 已批准并执行激活；未批准前保持 `draft`

## FE-05

**Code Review 前端检查项**

交付位置：`ai/skills/code-review/SKILL.md` 的前端检查段。

```markdown
## 前端审查检查项

### 必查
- [ ] 变更位于允许写路径，未越过共享边界
- [ ] 组件、状态、路由和数据访问遵循适用 Rule/Skill
- [ ] 用户可见状态与验收标准一致
- [ ] 鉴权、输入处理、敏感数据和依赖变化已按风险规则检查
- [ ] 适用测试已执行，失败或未执行项未被描述为通过
- [ ] 构建产物、调试内容、密钥和无关格式化未混入

### 阻塞规则
- 必须阻塞：<功能错误、安全/隐私风险、契约破坏、缺失强制证据等条件>
- 升级而非自行裁决：<跨模块、架构或产品范围争议>

### 不得仅以风格阻塞
- 已由自动格式化/Lint 覆盖且检查通过的个人偏好
- 未写入项目规则、无用户影响且不造成维护风险的主观写法
- 仅有替代偏好时，标记为非阻塞建议并说明收益
```

完成检查：
- [ ] 必查项覆盖正确性、边界、风险和测试证据
- [ ] 阻塞条件具体且能关联规则或实际影响
- [ ] 明确区分阻塞问题与非阻塞建议
- [ ] 不以未制度化的个人风格偏好阻塞合并
